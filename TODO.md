- **valgrind**: no memory errors or leaks on all 220 files.
- **fuzz**: 7,000 random mutations, no crash, hang or silent failure.
- **bench**: timings appended to [tests/history.csv](tests/history.csv) with the date and commit, to track the performance work.

The code passes `norminette` (src, `ft_nm.h`, libft).

**Deliberate differences from nm** (be ready to explain them):
- Cosmetic: `ft_nm:` prefix, `strerror` wording, no `Warning:` prefix, specific reasons for corrupt files.
- An empty file reports "file format not recognized" (nm is silent).
- Corrupt section headers, symbol tables, string tables or section names stop with an error and exit 1. Depending on the case, nm prints "no symbols", lists what it can, or exits 0.
- A malformed archive, or a member that fails, gives exit 1 (nm exits 0). Thin archives are refused.
- An unterminated symbol string table: the name is printed as `<corrupt>` with a warning. nm silently cuts it short.
- A section index past the table prints `A`, like nm (commented in the code).
- Any `e_machine` is accepted, like nm. `e_ehsize` and `e_type` are not checked, also like nm.

## P0 — Blocking

- [ ] **1. Performance.** The insertion sort is O(n²), and `strcoll` is slower than `strcmp`. Output is one `write()` per character.
  - 50,000-symbol `.o`: **17.5 s** (`nm`: 0.05 s). 10,000 symbols: 0.74 s. `libc.so.6`: 0.29 s (`nm`: 0.02 s).
  - Printing libc makes **295,815 `write` syscalls** for 8,122 lines.
  - Fix: a stable merge sort, which keeps equal names in symbol-table order (needed to match libc). Buffer the output, for example a 4 KiB buffer flushed when full and at the end of each file. Flush stdout before writing an error so the two streams stay in order. Keep every new file within the Norm.
  - Check the gain with `make test`: the bench rows in `tests/history.csv` keep every run.
