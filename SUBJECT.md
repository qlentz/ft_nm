## Chapter I — Foreword

**theorem 1** (Lagrange)**.** *For any finite group G, the order (number of elements) of every subgroup H of G divides the order of G.*

*Proof.* Let ∼ be the relation defined by: for all x, y ∈ G, x ∼ y if and only if there exists a ∈ H such that ax = y. Let's show that ∼ is an equivalence relation.

**reflexivity** 1x = x.

**Symmetry** if ax = y then x = a⁻¹y.

**transitivity** If ax = y and by = z, then (ba)x = z

The equivalence classes of ∼ form a partition of G. For x ∈ G, let cl(x) = Hx. If we show that all classes have the same cardinality, then we show that the cardinality of cl(1) = H divides the cardinality of G.

Let a, b ∈ G. Let us define a bijection from Ha to Hb. Let f : Ha ⟶ Hb as for all x in G, f(x) = xa⁻¹b. Let g : Hb ⟶ Ha as for all x in G, g(x) = xb⁻¹a. For all x ∈ G, f(g(x)) = xb⁻¹aa⁻¹b = x and g(f(x)) = xa⁻¹bb⁻¹a = x. So g = f⁻¹. ∎

To complete this project, you will have to use a Linux OS. You may use Docker or a virtual machine if needed. You have to work with ELF binaries. You have to handle x86_32 and x86_64 binaries, object files, and shared libraries (.so).

Be aware that on recent Ubuntu versions (20.04+), most system binaries are stripped of symbols. Since this project relies on symbol table inspection, you are expected to test your program on non-stripped binaries (the recommended VM environment).

Use the `file` command to view details about a file. You can use the binaries located in your system (`/usr/bin/`, `/usr/lib/`...).

> ℹ️ `man nm`

- This project will be corrected by humans only. You're allowed to organize and name your files as you see fit, but you must follow the following rules.
- The executable must be named `ft_nm`
- You must code in C and use a Makefile.
- Your Makefile must compile the project and contain the usual rules.
- If you choose to do so, you may use your own library for `ft_nm`. Also submit your `libft` folder including its own `Makefile` at the root of your repository. Your Makefile will have to compile the library, and then compile your project.
- Output is to be similar to nm on the symbols list (order, offset, padding...). Other aspects can have some small differences (filename, etc).
- Your program must behave like the system nm on every other aspect. You have to handle errors carefully. In no way can your program quit in an unexpected manner (Segmentation fault, bus error, double free, etc).
- Be cautious. There are many ways to lead your program out of the mapped content, may it be with non-null terminated string, incorrect offsets... Check everything.
- Make sure that every value that you parse is correct: for instance, when parsing flags, architecture, match your result with a reference to ensure its value is correct.
